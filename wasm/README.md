# OpenACR WASM Demo — AMC-Generated C++ in the Browser

This demo compiles AMC-generated C++ code to WebAssembly and runs it in a web browser.
The same in-memory database (`samp_mdb`) that runs natively on the server also runs
as WASM in the browser, with both sides communicating via ssim tuples over WebSocket.

## What This Proves

1. **AMC-generated code runs in browsers** — Tpool allocators, Thash indexes, Llist traversal,
   ssim parsing/printing — all compiled from C++ to WASM via Emscripten
2. **Same code, two runtimes** — the Node.js server loads the same `samp_mdb.wasm` module;
   the browser loads the identical binary
3. **ssim as wire protocol** — records are serialized/deserialized using AMC-generated
   `Print`/`ReadStrptrMaybe` functions on both ends
4. **Real-time sync** — multiple browser clients maintain synchronized in-memory databases
   through a WebSocket server
5. **Live data streaming** — server generates price quotes, pushes to browsers via WebSocket,
   browsers insert into their local WASM database and render a live chart

## Architecture

```
┌─────────────────────┐         WebSocket          ┌──────────────────────┐
│   Node.js Server    │◄──────── ssim tuples ──────►│   Browser (WASM)     │
│                     │                             │                      │
│  samp_mdb.wasm      │   { type: "quote",          │  samp_mdb.wasm       │
│  ├─ Tpool (User)    │     quote: {symbol, price} } │  ├─ Tpool (User)     │
│  ├─ Thash (ind_user)│                             │  ├─ Thash (ind_user) │
│  ├─ Llist (zd_user) │   { type: "sync",           │  ├─ Llist (zd_user)  │
│  ├─ Tpool (Quote)   │     records: ["ssim..."] }  │  ├─ Tpool (Quote)    │
│  └─ Llist (zd_quote)│                             │  └─ Llist (zd_quote) │
│                     │   { type: "insert",          │                      │
│  Quote generator    │     ssim: "samp_mdb.User.." }│  Canvas chart        │
│  (1/sec, 3 symbols) │                             │  (redrawn every sec)  │
└─────────────────────┘                             └──────────────────────┘
```

## Schema (samp_mdb)

Defined in `data/dmmeta/*.ssim`, generated by `amc`:

| Type | Primary Key | Fields | AMC Data Structures |
|------|-------------|--------|---------------------|
| User | `user` (Smallstr50) | email, role | Tpool + Thash + Llist |
| Project | `project` (Smallstr50) | description, status | Tpool + Thash + Llist |
| Task | `task` (Smallstr50) | title, priority, status, p_project, p_user | Tpool + Thash + Llist + Bheap |
| Comment | `comment` (Smallstr50) | p_task, p_user, text | Tpool + Thash + Llist |
| Quote | `quote` (Smallstr50) | symbol, price, ts | Tpool + Llist |

## Dependencies

### Build-time
- **Emscripten SDK (emsdk)** — C++ to WASM compiler
  ```bash
  git clone https://github.com/emscripten-core/emsdk.git ~/emsdk
  cd ~/emsdk && ./emsdk install latest && ./emsdk activate latest
  ```
- **OpenACR (amc)** — code generator (this repo)

### Runtime
- **Node.js** (v18+) — runs the sync server
- **npm** — installs the `ws` (WebSocket) package
- **Modern browser** — Chrome, Firefox, Safari, Edge (WebAssembly support)

## How to Build

### 1. Generate C++ from schema (if schema changed)
```bash
bin/amc
```

### 2. Generate embind bindings
```bash
bin/wasm-gen samp_mdb
```

This reads `data/dmmeta/*.ssim` and auto-generates `cpp/samp_mdb/wasm_bind.cpp` with:
- `init()` — FDb initialization + Tpool Reserve calls
- `insertSsim(str)` — type-tag dispatch to AllocMaybe/ReadStrptrMaybe/XrefMaybe
- `toSsim(type, key)` — Thash lookup + Print serialization
- `*List()` / `*Count()` — for each FDb Llist (zd_*)
- `*Find(key)` — for each FDb Thash (ind_*)
- `EMSCRIPTEN_BINDINGS` registration

**This works for any AMC namespace**, not just samp_mdb. The generator derives
everything from the schema — no hand-written per-type code needed:
```bash
bin/wasm-gen <namespace>   # generates cpp/<ns>/wasm_bind.cpp
```

### 3. Compile to WebAssembly
```bash
bin/wasm-build
```

This runs `em++` with Emscripten, compiling the following source files:
- `cpp/samp_mdb/wasm_bind.cpp` — embind bindings (generated by wasm-gen)
- `cpp/gen/samp_mdb_gen.cpp` — AMC-generated samp_mdb code
- `cpp/gen/dmmeta_gen.cpp` — AMC-generated meta-information
- `cpp/gen/_gen.cpp` — AMC-generated primitive type parsers
- `cpp/gen/algo_gen.cpp`, `cpp/gen/algo_lib_gen.cpp` — AMC-generated algo library
- `cpp/lib/algo/*.cpp` — hand-written algo library (string, fmt, crc32, etc.)

Output: `wasm/build/samp_mdb.js` (81KB) + `wasm/build/samp_mdb.wasm` (218KB)

### 4. Install server dependencies
```bash
cd wasm && npm install
```

## How to Run

### Quick start
```bash
cd wasm
npm install        # first time only
node server.js     # starts on port 9090
```
Open http://localhost:9090 in a browser.

### With start/stop scripts
```bash
wasm/start.sh              # starts server + optional ngrok tunnel
wasm/stop.sh               # stops everything
wasm/start.sh --no-ngrok   # without ngrok
```

## Portability: CRC32 Shim

OpenACR uses SSE4.2 CRC32C intrinsics (`_mm_crc32_u8/u16/u32/u64`) for hash table
operations. WASM doesn't have SSE4.2, so `include/wasm_crc32_shim.h` provides a
software CRC32C implementation using the Castagnoli polynomial. This shim is
force-included via `-include` during compilation and sets `WASM_CRC32_SHIM_DEFINED`
to prevent `algo.inl.h` from redefining the intrinsics.

Additionally, the shim handles Emscripten's stdio macro conflicts (`stdout`, `stdin`,
`stderr`) which collide with OpenACR's generated struct field names.

## Portability: Emscripten Embind

`cpp/samp_mdb/wasm_bind.cpp` bridges C++ and JavaScript using Emscripten's `embind`:

| JavaScript | C++ (AMC-generated) |
|------------|---------------------|
| `M.init()` | `algo_lib::FDb_Init()`, `samp_mdb::FDb_Init()`, `*_Reserve()` |
| `M.insertSsim(str)` | `GetTypeTag()` → `*_AllocMaybe()` → `*_ReadStrptrMaybe()` → `*_XrefMaybe()` |
| `M.toSsim(type, key)` | `ind_*_Find()` → `*_Print()` |
| `M.userList()` | `zd_user_First()` / `zd_user_Next()` iteration |
| `M.quoteCount()` | `zd_quote_N()` |
| `M.quotePrune(cutoff)` | `zd_quote_First()` / `zd_quote_Next()` / `quote_Delete()` |

The binding also provides stubs for OS-level functions not available in WASM
(`FatalErrorExit`, `FileToString`, `WriteFile`, `fildes_Cleanup`, `giveup_time_Step`).

## WebSocket Protocol

All messages are JSON. The ssim data inside is the standard OpenACR ssim tuple format.

### Server → Client
```json
// On connect: full database state
{ "type": "sync", "records": ["samp_mdb.User  user:alice  email:alice@example.com  role:developer", ...] }

// On connect: quote history (last 10 min)
{ "type": "quote_history", "quotes": [{"ts":1742558000,"symbol":"AAPL","price":185.50}, ...] }

// Every second: live quote
{ "type": "quote", "quote": {"ts":1742558001,"symbol":"GOOG","price":175.20} }

// When another client inserts a record
{ "type": "insert", "ssim": "samp_mdb.User  user:charlie  email:charlie@example.com  role:intern" }

// Acknowledgement of client insert
{ "type": "ack", "ok": true, "ssim": "..." }
```

### Client → Server
```json
// Insert a new record
{ "type": "insert", "ssim": "samp_mdb.User  user:charlie  email:charlie@example.com  role:intern" }
```

## Demo Script

1. **Open the page** — chart starts rendering immediately with live AAPL/GOOG/TSLA prices
2. **Open DevTools Console** and type:
   ```js
   M.quoteCount()    // number of quotes in WASM database
   M.userList()      // AMC hash index lookup, linked list iteration
   M.insertSsim('samp_mdb.User  user:demo  email:live@demo  role:viewer')
   M.userCount()     // incremented — C++ Tpool allocation happened in the browser
   ```
3. **Open two tabs** — add a user in one, it appears in the other (WebSocket broadcast)
4. **Show the schema** — `data/dmmeta/ctype.ssim` and `data/dmmeta/field.ssim` are the
   entire type definitions. `amc` generates all the C++ from these text files.
5. **Key message**: "The same C++ binary that could run a trading system at native speed
   is running in your browser right now. Zero hand-written serialization — amc generates
   everything from two-line schema definitions."


## Known Limitations

- **Node.js server, not native C++** — the server runs the WASM module in Node.js V8,
  not as a native C++ binary. A native C++ server using `lib_http`/`lib_ws` is a future goal.
- **No server-initiated push on direct DB mutation** — if the server database changes
  without a client request, connected browsers are not notified (except for quotes which
  use a dedicated broadcast).
- **ERROR_ON_UNDEFINED_SYMBOLS=0** — some OS-level symbols referenced by algo_lib
  are stubbed out at runtime rather than link-time. These are functions not needed in
  WASM (file I/O, timers, regex).
